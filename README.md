# コンペ会場（SolidJS + Go）

お題と期間つきの匿名コンペサイト。作者名は結果発表まで伏せられ、ポイント合計で順位が決まります。

## 期間の流れ

```
[開催前] ─① 受付開始─ [投稿期間] ─② 投稿締切─ [投票期間] ─③ 投票締切─ [結果発表]
            投稿・閲覧・投票・コメント      閲覧・投票・コメント        作者名・あとがき・順位を公開
            作者は投稿期間中だけ編集・削除できる
```

- 匿名化は **サーバー側（Go）で** 行っています。結果発表前は API がペンネーム・あとがき・得点を一切返しません（ブラウザの開発者ツールで見ても分かりません）。
- 投票：1作品につき「1〜10 pt＋一言感想（5文字以上・必須）」を1票。後から変更・取り消し可。順位は合計 pt（同点なら票数の多い順、それも同じなら同順位）。
- 票の感想と点数は結果発表まで非公開。発表後は作品ページに「投票と感想」一覧と点数分布グラフが出る。
- 匿名期間中の作品一覧は、並び順による有利不利を減らすため、初期状態はランダム順です。

## 構成

```
compe/
├─ server/          Go（標準ライブラリのみ・外部依存なし）
│  ├─ main.go       API・匿名化・投票・ランキング
│  ├─ store.go      データモデル・JSONファイル保存・パスワードハッシュ(PBKDF2)
│  └─ dist/         ← フロントのビルド結果（バイナリに埋め込まれる）
└─ web/             SolidJS + Vite（ハッシュルーティング：/#/contests/...）
   └─ src/
      ├─ pages.tsx      一覧・コンペ・投稿・閲覧・編集・管理の各画面
      ├─ EntryForm.tsx  投稿フォーム（入力 → プレビュー → 投稿）
      ├─ components.tsx 期間タイムライン・カウントダウン・作品カード・タグ入力など
      ├─ markup.ts      ルビ・傍点記法
      └─ api.ts         API 呼び出し・サイト名
```

## 動かし方

### おすすめ：GitHub Codespaces（ブラウザだけで動く・PCを汚さない）

1. GitHub のこのリポジトリで「Code」→「Codespaces」→「Create codespace on main」
2. 準備が終わるのを待つ（初回は数分。Go と Node.js は自動で入る）
3. 下のターミナルで `./run.sh`
4. 右下に出る「ブラウザーで開く」を押す（または「ポート」タブの 8080 の地球儀アイコン）
5. 管理画面のトークンは `dev-admin`

- 使い終わったら codespace を「停止」しておく（無料枠は月あたりの使用時間で決まるため。放置しても一定時間で自動停止する）
- 壊したら codespace を削除して作り直せば元どおり

### 自分のPCで動かす

必要：Go 1.24 以上、Node.js 20 以上

```bash
cd web && npm install && npm run build     # server/dist にビルド
cd ../server
ADMIN_TOKEN=好きな長い文字列 HASH_SECRET=別の長い文字列 go run . -demo
# → http://localhost:8080
```

`-demo` はデータが空のときだけ、受付中と結果発表済みのデモコンペを作ります（デモ作品の編集パスワード：`demo`）。

本番は `go build -o compe .` でできた1ファイルを置いて実行するだけです。

### Windows（PowerShell）

いちばん簡単なのは、フォルダの `run.cmd` をダブルクリックするか、PowerShell で `.\run.cmd` と打つ方法です（管理トークンは `dev-admin`）。

手で打つ場合、PowerShell では環境変数の書き方が違います。

```powershell
cd web
npm.cmd install
npm.cmd run build
cd ..\server
$env:ADMIN_TOKEN = "dev-admin"
$env:HASH_SECRET = "dev-secret"
go run . -demo
```

- `npm` ではなく `npm.cmd` と打つのは、「このシステムではスクリプトの実行が無効になっている」というエラーを避けるためです
- Windows PowerShell 5.1 では `&&` が使えないので、1行ずつ打ちます

### 開発中（画面を即時反映したいとき）

```bash
cd server && ADMIN_TOKEN=dev go run . -demo   # API: 8080
cd web && npm run dev                         # 画面: 5173（/api は 8080 へ転送）
```

## 設定

| 項目 | 内容 |
|---|---|
| `-addr` | 待ち受けアドレス（既定 `:8080`） |
| `-data` | データファイル（既定 `data/compe.json`）。バックアップはこのファイルをコピー |
| `ADMIN_TOKEN` | 管理画面（/#/admin）のログイン用。未設定だと起動ごとに一時トークンをログに出す |
| `HASH_SECRET` | 投票者キー・IPのハッシュ用の秘密値。**必ず設定**し、運用中は変えない |
| `STRICT_IP=1` | 同じIPからの同一作品への二重投票も拒否（携帯回線では同じIPを共有することがあるので既定はオフ） |
| `TRUST_PROXY=1` | nginx 等の後ろで動かすとき、X-Forwarded-For を信用する |
| サイト名 | `web/src/api.ts` の `SITE_NAME` と `web/index.html` の `<title>` |
| 感想の最低文字数 | `server/votes.go` の `MinCommentLen` と `web/src/api.ts` の `MIN_VOTE_COMMENT` |
| ポイント上限 | `server/votes.go` の `MaxPoints` と `web/src/api.ts` の `MAX_POINTS`（両方そろえる） |

## 管理者ができること

- **票の確認**（管理画面 → 各コンペの「票を確認」）：途中経過の得点と全票を見られ、怪しい票に目印が付く。不正と判断した票は1票ずつ削除できる
  - 「短時間に集中」：同じ作品へ10分以内に3票以上（`server/votes.go` の `BurstWindow` / `BurstCount` で調整）
  - 「同じIPから複数票」：同じ回線から別ブラウザ扱いで同じ作品に複数票
  - 「同じ感想文」：コンペ内に同じ文面の感想（記号・空白の違いは無視）
  - 目印は「疑い」。人気作に自然に票が集まることもあるので、感想の中身を見て判断する
- /#/admin でコンペの作成・編集・削除（お題・説明・3つの日時）
- ログイン中は、どの作品の「編集・削除」もパスワードなしで可能（荒らし対策）。コメントも同様
- 作者は自分の作品の編集パスワードで、その作品についたコメントを削除できる

## 既知の制限（必要になったら足すもの）

- 不正投票対策はブラウザ単位（localStorage のキー）＋任意でIP。ブラウザを変えれば再投票できる
- 書き込みの回数制限（レート制限）はない。公開運用では nginx 側で制限をかけると安心
- データは1つのJSONファイル。作品数が数千を超えるようなら SQLite へ移す
